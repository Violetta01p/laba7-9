Лабораторна робота №7-9
Тема: Розробка вебдодатка «Cyber Clicker Pro» на базі бібліотеки React та інструменту збірки Vite
1. Функціонал програми (Подієвий опис)
Подія: Клік по головній кнопці сайту Програма збільшує баланс ігрової валюти (кредитів) на величину сили кліку. Одночасно оновлюється лічильник загальної кількості зароблених за гру грошей.

Подія: Натискання кнопки «Купити» в магазині покращень Програма зчитує тип обраного товару, порівнює поточну вартість із балансом користувача, списує кошти та додає +1 рівень до цього покращення.

Подія: Натискання кнопки «Відкрити кейс» З балансу списується фіксована сума (100 кредитів). Запускається рандомайзер із ймовірністю 50/50. Результат: або повне анулювання ставки, або зарахування виграшу (500 кредитів).

Подія: Натискання кнопки «Активувати Престиж» Доступно при накопиченні від 10 000 кредитів. Програма повністю обнуляє поточний баланс та рівні магазину, але нараховує постійну преміум-валюту, яка збільшує пасивний дохід у наступному циклі гри.

Подія: Натискання кнопки вибору тему (Світла / Темна / Неон) Програма змінює рядок стану теми в коді. Весь інтерфейс сайту миттєво розфарбовується без перезавантаження сторінки.

Подія: Настання кожної нової секунди (Внутрішній таймер) Автоматично нараховується пасивний дохід. З ймовірністю 2% генерується хакерська атака (активується антибонус), яка накладає штрафи на працездатність гри.

Подія: Закриття та повторне відкриття вкладки браузера При закритті дані записуються в пам'ять. При відкритті програма зчитує збережений час, обчислює тривалість офлайну та нараховує компенсацію за пропущений час.

2. Циркуляція даних у додатку (Data Flow)
У додатку реалізовано концепцію односпрямованого потоку даних (Unidirectional Data Flow), де керування станом централізоване, а дані передаються зверху вниз через механізм Props:

   [ useClicker.js (Кастомний хук / Сховище станів) ]
       │            │               │             │
    Props        Props           Props         Props
       ▼            ▼               ▼             ▼
[<StatusBar />] [<ClickButton />] [<Upgrades />] [<PrestigeAndSkins />]
Низхідний потік (Downstream): Кастомний хук useClicker.js виступає єдиним джерелом істини (Single Source of Truth). Стани credits, prestigeCoins, currentSkin та обчислений пасивний дохід передаються в дочірні UI-компоненти для рендерингу.

Висхідний потік (Upstream / Callbacks): Інтерактивні дочірні компоненти не мають права змінювати глобальний стан напряму. При натисканні кнопок усередині <ClickButton /> або <Upgrades /> вони викликають передані їм через пропси функції-колбеки (handleClick, buyUpgrade, openCase), які сигналізують хуку про необхідність виконати мутацію стану.

3. Реалізація принципів ООП у структурі проєкту
Інкапсуляція: Вся бізнес-логіка, збереження станів гри (стейтів) та формули розрахунків повністю ізольовати всередині кастомного хука useClicker.js. Зовнішні UI-компоненти інтерфейсу (кнопки, панелі) не мають прямого доступу до модифікації даних. Взаємодія відбувається виключно через закриті функції-модифікатори (handleClick, buyUpgrade), що унеможливлює випадкове пошкодження даних ззовні.

Успадкування: Всі об'єкти ігрового магазину (товари) не описуються окремо, а створюються на основі єдиного базового шаблону (структури об'єкта). Кожен елемент магазину автоматично успадковує обов'язковий набір властивостей: name (назва), level (учень класу рівня), baseCost (базова ціна) та income (коефіцієнт прибутку). На основі цього спадкового масиву будується вся логіка магазину.

Поліморфізм: Реалізований через універсальний метод купівлі buyUpgrade(type). Замість створення окремих функцій під кожен товар, інтерфейс використовує один загальний метод. Залежно від переданого параметру (type), функція демонструє різну поведінку: для об'єкта класу «Мишка» вона модифікує силу активного кліку, а для об'єктів пасивного типу (наприклад, «Сервер») — змінює глобальний щосекундний дохід.

4. Специфікація використаних React-хуків
Керування станом (Хук useState)
const [credits, setCredits] = useState(0); — числове значення поточного балансу активної валюти.

const [totalCredits, setTotalCredits] = useState(0); — лічильник усього накопиченого прибутку за поточну ітерацію для перевірки умов престижу.

const [prestigeCoins, setPrestigeCoins] = useState(0); — кількість преміум-монет, що діють як постійний множник доходу.

const [currentSkin, setCurrentSkin] = useState('skin-default'); — строковий ідентифікатор активної теми CSS.

const [activeDebuff, setActiveDebuff] = useState(null); — стан для збереження поточної хакерської загрози ('virus', 'ddos', 'bug' або null).

Керування життєвим циклом та побічними ефектами (Хук useEffect)
Ефект монтування ([]): Спрацьовує один раз під час завантаження додатка. Ініціалізує виклик функції loadGame() для відновлення сесії та нарахування офлайн-прибутку.

Ефект ігрового циклу: Розгортає асинхронний таймер setInterval з кроком 1000 мс. Кожну секунду здійснює мутацію стану балансу (додає пасивний дохід) та виконує логічну перевірку шансу запуску шкідливого ПЗ (Math.random() < 0.02). При розмонтуванні компонента викликає clearInterval для очищення пам'яті.

Ефект автозбереження ([credits, upgrades]): Відстежує зміни ключових стейтів додатка і автоматично перезаписує актуальний стан у локальне сховище.

5. Конкретний розбір функцій та методів (useClicker.js)
handleClick() * Вхідні дані: Подія onClick на головній кнопці.

Алгоритм: Викликає функцію setCredits(prev => prev + clickPower). Збільшує стейт поточного гаманця та стейт totalCredits на вираховане значення сили кліку.

getClickPower() * Алгоритм: Перевіряє рівень прокачки елемента мишки в масиві магазину. Якщо в стейті антибонусів зафіксовано статус activeDebuff === 'virus', функція ділить фінальний результат на 2. Повертає підсумкову силу кліку.

getPassiveIncome() * Алгоритм: Проводить калькуляцію: сумує дохід від усіх куплених об'єктів магазину та множить на коефіцієнт монет престижу. Містить логічне розгалуження: якщо activeDebuff === 'ddos', функція ігнорує всі рівні об'єктів і миттєво повертає 0.

buyUpgrade(type) * Вхідні дані: Строковий ідентифікатор об'єкта (type).

Алгоритм: Звертається до утиліти calculateCost для отримання актуальної ціни. Виконує перевірку умови if (credits >= currentCost). При успіху: віднімає суму від стейту credits, знаходить потрібний type в масиві та збільшує його level на 1.

openCase() * Алгоритм: Зменшує стейт credits на 100 одиниць. Викликає метод Math.random(). Якщо згенероване число більше за 0.5, запускає setCredits(prev => prev + 500). У протилежному випадку баланс не змінюється.

triggerPrestige() * Алгоритм: Виконує перевірку if (totalCredits >= 10000). При істинності умови скидає стейт credits до 0, а рівні всіх елементів магазину встановлює у вихідне положення (0). Одночасно вираховує та додає нові монети в стейт prestigeCoins.

6. Специфікація допоміжних модулів
formulas.js (Математичні розрахунки): * Функція calculateCost: Приймає базову ціну та рівень. Повертає значення, розраховане як ціна, помножена на 1.5 в ступені поточного рівня. Результат обробляється методом Math.floor() для приведення до цілого типу.

Функція calculatePrestigeCoins: Приймає історичний баланс, застосовує до нього операцію квадратного кореня відносно ліміту гри та повертає ціле число нових монет.

storage.js (Утиліта збереження даних): * Функція saveGame: Приймає поточний стан усіх стейтів, додає системний прапорець Date.now() і записує рядок через localStorage.setItem().

Функція loadGame: Викликає localStorage.getItem(), розбирає рядок через JSON.parse(). Віднімає від поточного часу збережений таймстамп, отримуючи секунди офлайну. Множить ці секунди на показник пасивного доходу та повертає стартовий баланс із урахуванням офлайн-нарахування.

7. Обробка виняткових ситуацій та стійкість коду (Error Handling)
Запобігання дефіциту балансу (Валідація транзакцій): У функціях buyUpgrade та openCase інтегровано умовні оператори перевірки фінансового стану. Якщо спроба виклику методу відбувається при незадовільному стані стейту credits, транзакція автоматично блокується, упереджуючи появу від'ємних значень на балансі.

Безпечне зчитування з LocalStorage (Блок try...catch): Операції парсингу текстових збережень у модулі storage.js загорнуті в конструкцію захисту try...catch. Якщо структура даних у пам'яті браузера пошкоджена або модифікована користувачем ззовні, метод JSON.parse() не ламає роботу додатка (не викликає Fatal Error), а перехоплює виняток, занулює пошкоджений сектор сховища та ініціалізує безпечний старт нової ігрової сесії з дефолтними параметрами.

8. Архітектура компонентів (Інтерфейсна розмітка)
<StatusBar /> — Відображає текстові блоки з даними про стан стейтів: загальний баланс, пасивний прибуток/сек, силу кліку та монети престижу.

<ClickButton /> — Містить елемент <button onClick={handleClick}> (головна кнопка дії) та <button onClick={openCase}> (активація лотерейного кейсу).

<Upgrades /> — Використовує метод перебору масиву .map(). Генерує для кожного об'єкта магазину блок картки. Керує станом доступності кнопок покупки через логічний атрибут disabled={credits < currentCost}.

<PrestigeAndSkins /> — Контейнер функціональних кнопок управління. Містить кнопку виклику методу triggerPrestige та три окремі кнопки зі слухачами onClick={() => changeSkin('назва_теми')}.

Блок сповіщень в <App /> — Логічний вузол умовного рендерингу. Відображає HTML-блок з попередженням про атаку тільки у випадку, якщо стейт поточного антибонусу не є порожнім (activeDebuff !== null).

9. Керування стилями (Themes.scss)
Динамічна прив'язка класів: Корневий тег отримує стилізацію через шаблонний рядок: className={\app-container ${currentSkin}`}`.

Вкладеність архітектури SASS: Стилі жорстко розподілені по внутрішніх блоках .skin-default, .skin-dark, .skin-neon. Зміна стейту скіна в React автоматично перемикає властивості background-color та color для всього DOM-дерева без перезавантаження сторінки.

UX-анімація взаємодії: Для плавного переходу кольорів задано параметр transition: all 0.3s ease. Фізичний відгук кнопок при натисканні реалізовано через псевдоклас &:active { transform: scale(0.96); }.
